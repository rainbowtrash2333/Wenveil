# ADR-0001：混合式确定性可逆脱敏架构

> 版本：V0.3（2026-09-16）｜状态：已接受
> 日期：2026-09-12
> 关联：[ARCHITECTURE.md](../ARCHITECTURE.md)、[MODULES.md](../MODULES.md)、[脱敏设计规格](../ocr_desensitization_implementation_plan.md)

## 背景

金融 OCR 文档同时包含可由正则确定识别的字段、机构简称/子公司关系、人员名单和需要语义判断的实体。
交付文本要供后续大模型阅读，因此必须保留主体关系的可读语义，同时不能暴露原始名称；还必须支持完整恢复、
审计和离线运行。单一正则会漏掉上下文人名，单一生成式模型又可能改写数字、标点或原文结构。

## 决策

采用分层混合架构：Normalizer 先做确定性 OCR 规整；规则、词典、机构关系注册表和可选本地 NER 只产生
不可变 Span；Pipeline 通过统一 Resolver 处理优先级、重叠和受保护 Span；替换由确定性的 compact-v1 Token
一次性完成。可恢复模式将原始 surface、关系、文件名和哈希写入 AES-GCM 加密 mapping；无密码模式只落盘
masked 文本和安全报告，不落盘 mapping，因此明确不可恢复。

公共监管机构、宏观管理部门、行业自律组织和公开市场基础设施使用配置驱动的精确组织白名单，生成
`anonymize=false`、`protect=true` 的 ORG Span。若白名单名称只是更长非白名单机构候选的一部分，则丢弃
白名单子 Span，由更长候选整体脱敏，避免私有机构被部分放行。

机构关系不单独建立第二个完整模型：第一阶段由规则/词典/NER 找候选，第二阶段只对歧义候选做局部实体链接；
可以共享同一个 Qwen 主干和轻量 linking adapter。关系注册表独立于模型权重维护。

## 理由

- 确定性规则负责高风险格式字段和安全边界，便于审计、回归与离线部署。
- NER 只提出候选而不改写文本，降低模型幻觉和文档结构破坏风险。
- compact-v1 Token（如 `⟦机构1⟧`、`⟦机构1-别名1⟧`）比长占位符更省 Token，同时保留主体/关系语义。
- 白名单按词典评审即可变更，不需要重新训练；嵌套过滤防止白名单误放行私有主体。
- 可恢复模式的加密 mapping 与 masked 哈希绑定支持授权恢复，并让错误密码、篡改和文件错配显式失败；无密码模式避免生成未加密 mapping。

## 影响

- 生产包保持 Python 标准库、PyYAML 和 cryptography 的轻量依赖；模型依赖延迟加载。
- 规则和白名单修改必须增加回归测试，并更新专项方案/版本说明（如能力变化）。
- 下游大模型看到的是短语义 Token，不会看到真实机构/人员表面词；真实映射只在授权恢复时使用。
- 精确白名单可能需要持续人工维护；审计只覆盖已定义的高风险形态，不能替代正式数据集评估。
- 回滚方式是恢复上一版本规则、配置和代码；不绕过 mapping 校验，也不使用旧格式 Token 生成新文件。无密码结果不能通过后补密码变为可恢复结果，必须重新处理原文。

## 备选方案

1. **仅规则 + 全部机构脱敏**：实现简单，但会损失监管语境和主体关系信息，且无法覆盖上下文人名。
2. **两个完整模型分别做 NER 与关系推理**：资源和维护成本更高；当前采用共享主干、候选链接和独立注册表。
3. **模糊白名单/前缀放行**：可能把私有机构名称的公共子串误当成白名单，已明确不采用。
