# 文档管理手册（DOCUMENTATION-GUIDE）

> 版本：V0.2（2026-09-12）｜状态：生效
> 本文档定义 AICanRead 的**文档管理规范**：文档如何组织、如何写作、如何与代码
> 保持同步、冲突如何处理。任何文档新增/修改/删除前，先读本文档与 [index.md](./index.md)。

## 1. 目的与范围

1. 保证文档与代码同步：文档描述的架构、接口、命令、进度应与实际代码一致。
2. 保证文档之间无冲突：多份文档描述同一主题时不得互相矛盾。
3. **适用范围**：`docs/` 下全部文档、根目录 `AGENTS.md`、各工具链目录的 `README.md`。
4. **不在范围内**：`test-artifacts/`（测试产物，不入库）、`build/`、`dist/` 等产物目录。

## 2. 文档体系结构

```text
docs/
├── index.md                    # 唯一入口导航
├── DOCUMENTATION-GUIDE.md      # 本文档
├── ARCHITECTURE.md
├── MODULES.md
├── DEVELOPMENT-GUIDELINES.md
├── GIT-GUIDELINES.md
├── DEV-TOOLCHAIN.md
├── APP-VERSION.md
├── ROADMAP.md
├── adr/                        # 决策记录
└── archive/                    # 历史设计与方案资料
```

### 2.1 文档分类

| 分类 | 位置 | 变更时机 |
|------|------|----------|
| 项目级 | `docs/` 根目录 | 全局/跨模块决策 |
| 专项 | `docs/<topic>/` | 子系统相关 |
| UI 设计稿 | `docs/design/`（如项目有 UI） | 页面实现/审查时使用；无 UI 项目不创建此目录 |
| 决策记录 | `docs/adr/` | 重大技术路线变更 |
| 历史归档 | `docs/<topic>/archive/` | 方案完成后 |
| 工具链 README | 各脚本目录内 | 脚本接口变更时 |

## 3. 文档与代码同步原则（核心）

1. **代码是最终事实**：文档与代码冲突时，优先核对代码，再修正文档。除非代码确有 bug
   且已按流程修复，否则不得以文档改写代码行为。
2. **改代码必须同步文档**（同步矩阵）：

| 代码变更 | 必须同步的文档 |
|----------|----------------|
| 目录/包结构、模块划分 | `AGENTS.md`、`ARCHITECTURE.md`、`MODULES.md` |
| 公共接口/类名/枚举 | `ARCHITECTURE.md`、`MODULES.md`、对应专项 |
| 构建/测试/安装命令、脚本参数 | `DEV-TOOLCHAIN.md`、对应 `README.md` |
| 已实现/未实现能力、版本号、测试数量 | `APP-VERSION.md` |
| 阶段进度 | `ROADMAP.md` |
| 依赖版本 | `DEVELOPMENT-GUIDELINES.md`（以实际锁文件为准）、`APP-VERSION.md` |

3. **标注"现状/规划/远期"**：未实现项必须明确标注，不得写成已实现事实。
4. **运行期数据**（测试数量、体积等）以最新一次实际构建/运行为准，更新时间戳。

## 4. 文档写作规范

1. **语言**：正文用项目主语言，技术名词保留英文原名。
2. **文件命名**：全英文大写下划线（`APP-VERSION.md`）；已有中文名可沿用不改。
3. **头部元信息**：每份文档顶部包含 `> 版本：Vx.y（日期）｜状态：生效/设计中/规划中`，
   必要时列关联文档链接。
4. **链接**：`docs/` 内相对链接；目录间用 `../`；不允许断链。
5. **路径**：一律相对项目根目录；不得写死盘符与用户名，用环境变量。
6. **一句话职责**：每份文档只讲一个主题；交叉引用用链接而非复制内容。

## 5. 文档维护流程

### 5.1 新增文档
1. 判断归属分类（§2.1），按规范命名并写头部元信息。
2. **必须同步更新 `docs/index.md`**，并在相应分类登记。
3. 若属高频必读，同步更新 `AGENTS.md`（保持简短）。
4. 新增后自查：链接有效、与现有文档无重复矛盾。

### 5.2 修改文档
1. 更新头部 `版本/更新时间`。
2. 若主题或结构变了，检查 `docs/index.md` 与 `AGENTS.md` 描述是否仍准确。
3. 删除内容时，检查其他文档是否引用了被删章节，一并修正。

### 5.3 删除/重命名文档
1. 先全文搜索所有引用（`rg "旧文档名"`）。
2. 同步更新 `index.md`、`AGENTS.md`、其他文档中的链接。
3. 删除后不得残留断链。

### 5.4 重大技术决策（ADR）
技术路线变更先在 `docs/adr/` 记录讨论再实施；实施后同步 `ARCHITECTURE.md`、`ROADMAP.md`。

### 5.5 已完成方案归档
已完成的方案移入 `<topic>/archive/`，文件名附完成日期；归档前把仍有效的契约与限制
同步到正式文档；`index.md` 的快速决策表必须指向当前入口，不指向归档。

## 6. 索引与检索（docs/index.md）

`docs/index.md` 是全项目文档的**唯一入口导航**：

1. **AI 助手开工流程**：先读快速决策表定位，再按需精读，最后实施。
2. **必须同步**：任何文档的新增/改名/移动/删除，都必须同步更新索引。
3. **内容结构**：§1 快速决策表 / §2 项目级清单 / §3 专项 / §4 推荐阅读顺序 / §5 维护约定。

## 7. 文档冲突处理规则

| 冲突情形 | 处理原则 |
|----------|----------|
| 文档描述 vs 实际代码 | 以代码为最终事实，修正文档 |
| `AGENTS.md` vs `docs/index.md` | 以 index 为详细导航，AGENTS.md 仅摘要 |
| 测试规范冲突 | 以 `DEVELOPMENT-GUIDELINES.md` 为准 |
| Git 规范冲突 | 以 `GIT-GUIDELINES.md` 为准 |
| 设计稿 vs 已实现 UI | 有 UI 时标注设计稿状态；无 UI 项目不建立设计稿 |
| 版本号/依赖矩阵 | 以 `APP-VERSION.md` 与实际锁文件为准 |
| 阶段进度 | 以 `ROADMAP.md` 为准 |

## 8. 同步核对流程（合入前 Checklist）

- [ ] 涉及目录/模块/接口 → `AGENTS.md`、`ARCHITECTURE.md`、`MODULES.md` 已同步
- [ ] 涉及专项子系统 → 对应专项文档已同步
- [ ] 涉及命令/脚本 → `DEV-TOOLCHAIN.md` 与对应 `README.md` 已同步
- [ ] 涉及能力/版本/测试数量 → `APP-VERSION.md` 已更新（含时间戳）
- [ ] 里程碑完成 → `ROADMAP.md` 已勾选
- [ ] `docs/index.md` 链接与描述仍准确
- [ ] 全文无断链；无硬编码绝对路径
- [ ] 规划项均标注"阶段/远期/规划中"
- [ ] 提交范围符合 `GIT-GUIDELINES.md`
